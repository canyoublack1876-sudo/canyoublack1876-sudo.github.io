给 RAG 系统搭一条评估流水线

长李长庆·2026.10.08·11 min

上一篇写 FastGPT 知识库时提到，我把召回命中率从 62% 调到 87%。有朋友问这个数字怎么来的——不是拍脑袋，是跑了一条评估流水线。这篇展开讲这套流水线怎么搭，代码不多，思路值钱。

为什么需要评估

RAG 系统改任何一个变量——换 embedding 模型、调 chunk 大小、改检索 top_k——都可能让效果变好或变坏。没有评估，你就是在黑暗中调参，靠三两条手测问题判断"好像变准了"，然后上线被用户打脸。

评估流水线的目标：每次改动后，一键跑完测试集，输出可对比的指标。

第一步：造测试集

测试集是一组「问题 + 标准答案 + 期望召回的文档片段」。我从三个渠道攒了 120 条：

  • 真实用户的历史提问（最有价值，占 60 条）
  • 让 GPT 针对每篇文档生成 3 个问题（占 40 条）
  • 自己手写的边界 case：跨文档问题、文档里没有答案的问题（占 20 条）

三个血泪建议

测试集要持续养。 每周把用户点踩的对话加进测试集，评估才跟得上真实分布。我的测试集三个月从 50 条涨到 120 条。

judge 模型别省。 用弱模型当裁判，分数会虚高且不稳定，差的那点 API 钱远比不上误判带来的错误决策。

分开看分类型指标。 简单问题命中率 95%、多文档问题只有 60%，平均值 80% 会掩盖短板。报告里按 type 字段分组展示，短板一目了然。

有了这条流水线，调参从玄学变成了工程：改一行代码，跑十分钟，数据告诉你能不能上。
