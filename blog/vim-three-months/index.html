用 Vim 写了三个月代码，我留下了什么

长李长庆·2026.10.16·6 min

三个月前我把 VS Code 换成了 Neovim，原因很朴素：手腕疼，想减少手在键盘和鼠标之间的往返。现在三个月过去，结论是——我没有成为 Vim 原教旨主义者，但 VS Code 里永久装上了 Vim 插件。这篇记录这段折腾的始末和沉淀下来的东西。

第一周：想砸键盘

前三天效率掉到原来的三成。最崩溃的瞬间是想改一个单词，下意识按了 i，结果光标在单词中间，打出来的字插在了错误的位置。ciw（change inner word）这种神技，当时只会用 l 一下下挪。

坑一：别一上来就折腾插件和配置。我见过太多人（包括上周的我）花两天配出 IDE 级的 init.lua，然后连 hjkl 都用不顺，最后连编辑器带配置一起删了。先用裸 Vim 活过两周。

第二到六周：肌肉记忆形成

转折点在第三周。某天改 bug 时发现自己无意识打出了 f) 跳到括号、ct, 改到逗号，全程没碰鼠标。那一刻突然理解了 Vim 用户说的"编辑代码像说话"是什么意思——操作变成了组合动词，d（删）+ i"（引号内）= 删掉引号里的内容，这套语法一旦内化就回不去了。

这期间我只加了三个插件，刻意保持克制：

插件用途替代了什么
telescope模糊搜索文件Ctrl+P
nvim-tree文件树侧栏
LSP 官方客户端跳转定义/补全语言服务

第七周后：退烧与回归

退烧来得也很诚实。写前端时 JSX 的深度嵌套让 % 跳转频繁失灵，重构时 VS Code 的图形化重命名和多光标依然碾压我的宏操作。更要命的是团队协作——结对编程时同事看着我黑底绿字的屏幕满脸痛苦。

最终的落点是混合模式：回到 VS Code，装 VSCodeVim 插件，Normal 模式下的所有肌肉记忆原封不动，鼠标和 GUI 功能全部保留。Neovim 则留给服务器上改配置和写 commit message。

留下了什么

就算明天删掉 Vim 插件，这三样东西会跟我一辈子：

  1. 尽量少碰鼠标。 手不离开键盘，手腕疼确实缓解了，这是初衷，达到了。
  2. 组合式编辑思维。 ciw、di" 这种"动作 + 范围"的思维，让我对任何编辑器的快捷键都上手飞快。
  3. 对工具的钝感力。 折腾过编辑器圣战之后，再看"哪个 IDE 最好"的争论只觉得可爱——工具服务肌肉，肌肉服务产出。

如果你也想试，我的建议只有一条：设一个三个月的期限，期内不换工具、不加插件，到期再决定去留。折腾的沉没成本，比你想象的大。
